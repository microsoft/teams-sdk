# M365 Extensions

You already have a Teams SDK agent. M365 Extensions let you give it **multichannel** reach (one codebase that runs across Teams, Web Chat / Direct Line, email (Outlook), and other Microsoft Agents SDK channels) **by embedding your Teams SDK app as middleware in a Microsoft Agents SDK `AgentApplication`**. Your Teams-specific handlers keep working, and the Agents SDK handles everything else.

Practically, adding M365 Extensions to a Teams SDK agent lets you:

- **Reach beyond Teams.** The same agent responds on Web Chat, Direct Line, email, and other Agents SDK channels without rewriting your Teams handlers.
- **Keep Teams-native features.** Targeted messages, reactions, quoted replies, dialogs, and task modules still run through the Teams SDK when the activity comes from Teams.
- **Share one identity.** Teams API calls reuse the Agents SDK connection identity and tokens, so there's no second set of credentials to configure.

## How to Use It

<LanguageInclude section="setup" />

The bridge derives the Teams SDK app's identity and outbound tokens from the Agents SDK connection manager, so it works with your existing Teams SDK configuration. Don't pass separate client ID, tenant ID, or token options. If you're coming from a standalone Teams SDK app, move that configuration into the Agents SDK connection format.

Register Teams-specific routes on your Teams SDK bot. Register multichannel routes on your Agents SDK `AgentApplication`.

### Route Across Teams and Other Channels

M365 Extensions preserve the Agents SDK app's multichannel reach:

| Activity | Handled by |
| --- | --- |
| Teams activity matching a Teams SDK route | Teams SDK |
| Teams activity with no matching Teams SDK route | Agents SDK |
| Web Chat / Direct Line activity | Agents SDK |
| Email (Outlook) activity | Agents SDK |

## How It Works

The key intuitions:

- **One call wires everything.** `AddTeamsSdk<T>()` registers your Teams SDK bot and installs routing middleware on the Agents SDK adapter, reusing the Agents SDK connection identity for Teams API calls.
- **Non-Teams activities pass straight through.** They continue down the Agents SDK pipeline untouched.
- **Teams activities match before handling.** If a Teams activity matches a Teams SDK route, the Teams SDK handles it; otherwise it falls through to the Agents SDK. Nothing is consumed without a matching route.
- **Bypass when you need to.** An optional `shouldBypassTeams` predicate forces specific Teams activities (such as `signin/*` invokes) to stay on the Agents SDK pipeline.
