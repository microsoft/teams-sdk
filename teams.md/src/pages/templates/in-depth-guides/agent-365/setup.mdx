# Set up Agent 365

Before you run your agent with Teams SDK, provision its Agent 365 identity and Microsoft 365 resources. Use Agent 365 tools and Microsoft Learn for platform setup, then add the resulting values to your app.

## Prerequisites

You must set up these platform resources:

1. **Agent Identity Blueprint** and its service principal in the target tenant.
2. **Runtime credential** for the blueprint. We recommend managed identity or federated credentials in production. Use a client secret only for development.
3. **Public HTTPS callback** for the app's Activity Protocol endpoint, such as `https://<host>/api/messages`.
4. **Microsoft 365 agent package** that binds the Agentic User template to the blueprint.
5. **Agentic User** with the required license, manager, permissions, and workload onboarding.

Start with:

- [Agent 365 documentation](https://learn.microsoft.com/microsoft-agent-365/)
- [Register a custom client app](https://learn.microsoft.com/microsoft-agent-365/developer/custom-client-app-registration)
- [Plan an agent identity architecture](https://learn.microsoft.com/entra/agent-id/how-to-plan-agent-identity-architecture)
- [Agent 365 DevTools](https://github.com/microsoft/Agent365-devTools)

## Values needed by the app

An Agent Identity Blueprint uses the same authentication model as a standard Teams app. The blueprint ID is the application (client) ID.

| Agent 365 value      | App authentication setting                                                       |
| -------------------- | -------------------------------------------------------------------------------- |
| Blueprint ID         | Application (client) ID (`CLIENT_ID`)                                            |
| Blueprint credential | Client secret, user-assigned managed identity, or federated identity credentials |
| Tenant ID            | Tenant ID (`TENANT_ID`)                                                          |

Configure these values as described in <LangLink to="essentials/app-authentication/">App Authentication</LangLink>.

Agentic App Instance and Agentic User IDs are optional. Use them when your app needs to load a specific identity for a proactive operation.
