# Receiving Inline Images

When a user pastes an image into the Teams compose box, the image does not arrive inside <LanguageInclude content={{"typescript": "`activity.text`", "python": "`activity.text`", "csharp": "`Activity.Text`"}} />. Teams sends it as an attachment on the inbound message activity, and <LanguageInclude content={{"typescript": "`ctx.files`", "python": "`ctx.files`", "csharp": "`context.Files`"}} /> lists it alongside the files the user attached, as a lazy handle you can download from in the same way as an attached file.

## How pasted images are named and typed

A pasted image has no file name, so the SDK names it `image-<attachmentId>`. Its listed metadata comes from a format hint Teams sends with the message:

- <LanguageInclude content={{"typescript": "`name`", "python": "`name`", "csharp": "`Name`"}} /> gets an extension only for PNG, JPEG, GIF, or WebP, and <LanguageInclude content={{"typescript": "`extension`", "python": "`extension`", "csharp": "`Extension`"}} /> is taken from it, so it is absent when the name has none.
- <LanguageInclude content={{"typescript": "`contentType`", "python": "`content_type`", "csharp": "`ContentType`"}} /> is the matching MIME type for those four formats, otherwise `application/octet-stream`.
- <LanguageInclude content={{"typescript": "`uniqueId`", "python": "`unique_id`", "csharp": "`UniqueId`"}} /> is always unset, because a pasted image is not stored in OneDrive or SharePoint.
- <LanguageInclude content={{"typescript": "`contentUrl`", "python": "`content_url`", "csharp": "`ContentUrl`"}} /> is the image's Bot API location.

On the downloaded file, <LanguageInclude content={{"typescript": "`contentType`", "python": "`content_type`", "csharp": "`ContentType`"}} /> is detected from the bytes, and the extension of <LanguageInclude content={{"typescript": "`filename`", "python": "`filename`", "csharp": "`Filename`"}} /> follows it, so the downloaded file name can differ from the listed name. If the bytes are not PNG, JPEG, GIF, or WebP, the listed type is used.

:::note
Teams saves a pasted GIF as a static PNG. It is listed as `.gif` and `image/gif` but downloads as a PNG.
:::

## Formats that cannot be downloaded

Some image formats, such as BMP and AVIF, cannot be converted by the Teams service, so Teams shows a placeholder, and they cannot be downloaded. Downloading one of these fails with <LanguageInclude content={{"typescript": "`InlineImageTransformationError`", "python": "`InlineImageTransformationError`", "csharp": "`InlineImageTransformationException`"}} />. The same image sent as a file attachment downloads normally, so asking the user to resend it that way is the recovery:

<LanguageInclude section="errors-handling" />

If the Bot API refuses the token presented for the image, the download fails with <LanguageInclude content={{"typescript": "`InlineImageAccessError`", "python": "`InlineImageAccessError`", "csharp": "`InlineImageAccessException`"}} /> with a `401` or `403` status. Both errors share the common base error described in [Handle errors](./receiving-files#handle-errors).

## How the image is read

A pasted image is read from the Bot API with the same token the app uses to reply in that conversation, not through Microsoft Graph. This works for traditional bots and for agentic users, which read as their own identity. Inline images list and download in personal chats, group chats, and channels. Outside personal chats, only messages that @mention the agent reach it.

The token is sent only to a URL under the activity's `serviceUrl`. An inline image hosted anywhere else is skipped by <LanguageInclude content={{"typescript": "`list()`", "python": "`list()`", "csharp": "`ListAsync()`"}} /> with a warning in the log.

## Access the raw attachments

An inbound message with a pasted image typically contains two related attachments:

```json
{
  "attachments": [
    {
      "contentType": "image/png",
      "contentUrl": "https://.../v3/attachments/{id}/views/original"
    },
    {
      "contentType": "text/html",
      "content": "<p><img src=\"https://.../objects/{id}/views/imgo\" ...></p>"
    }
  ]
}
```

The listed file's <LanguageInclude content={{"typescript": "`raw`", "python": "`raw`", "csharp": "`Raw`"}} /> holds only the `image/*` attachment. The `text/html` attachment, which preserves where the image appeared among the message's text and other content, stays in <LanguageInclude content={{"typescript": "`ctx.activity.attachments`", "python": "`ctx.activity.attachments`", "csharp": "`context.Activity.Attachments`"}} />.
